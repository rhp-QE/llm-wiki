# Policy: Task Evidence Gate

Run this gate for every canonical task and canonical task update.

## Create Or Update `sources/tasks/` When

- The user marks the task as long-term, ongoing, recurring, routine, habit-forming, important, or review-worthy.
- The task or update records durable life, health, career, relationship, project, or learning evidence.
- The update records a meaningful execution event: milestone, substantial progress, repeated practice, missed routine with reason, blocker, unblock condition, failure, abandonment reason, completion outcome, or weekly/monthly review.
- The task is linked to a project, learning path, theme, event, report, or source whose future reconstruction depends on execution history.
- The user asks to preserve the task/update as evidence, says `入库`, `沉淀`, `记录到 wiki`, or `记为证据`.

## Do Not Create Task Evidence For

- Lightweight one-off todos.
- Dashboard ordering or cleanup.
- Simple status moves with no durable context.
- Typo fixes.
- Priority changes without durable reason.
- Daily done/not-done checkboxes with no user-provided observation.
- Agent-inferred outcomes not backed by source evidence.

## Preservation

Preserve raw user task/update wording verbatim in `## Raw Material`. For repeated check-ins, prefer grouped monthly records and preserve each update as a fragment with timestamp, origin, and original wording.
